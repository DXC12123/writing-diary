01产品概述

1.1 一句话

给「想每天写点东西，但一打开空白页就不知道写什么、写完又总想改」的人，一个先给九个问题、写完就封存的本地日记本。

1.2 背景与问题

常见的日记应用解决的是「记录」，但真正让人放弃写日记的是两件事：

问题表现本产品的应对
空白页焦虑打开编辑器，光标闪几下，不知道从哪句开始，关掉。九宫格预置写作提示，写作时可随时调出，不必从头想。
反复修改写完后反复回看、删改，把记录变成了作品，最后干脆不写。提交即锁定，永久只读；页面明确告知不可撤销。
任务化与焦虑连续打卡、字数统计、年度报告把日记变成 KPI。不做连续天数、不做提醒红点、不做排行榜；字数只做轻量展示。
隐私顾虑日记上云、上账号，心理门槛高。零账号、零上传，数据只在本机浏览器。

1.3 目标用户与场景

  • 主用户：有写日记意愿、但缺少「下笔理由」的个人用户，手机为主，一天一次，通常 3–10 分钟。
  • 场景 A · 睡前回顾：躺下后打开，看一眼九个问题，挑一两个顺着写，写完提交，结束。
  • 场景 B · 碎片时间：通勤或午休写一半，没写完也没关系，草稿在本机留着，晚上接着写。
  • 场景 C · 回看：周末翻月历，看哪几天写过、写了多少字，点开某天读一遍。

1.4 产品原则

编号原则含义与取舍
P1本地优先没有账号、没有服务端、没有网络请求。隐私是默认状态，不是设置项。
P2少即是好只有三个 Tab、一个浮层、一个详情页。任何新功能都要先回答「它会让写日记这件事变重吗」。
P3写完即封存锁定是产品的核心动作，不是保险措施。锁定的仪式感本身在降低「反复修改」的冲动。
P4不制造焦虑不惩罚断更、不制造 streak、不做成就体系。回顾只呈现事实，不评价。
P5纸的质感暖白纸色 + 宋体正文 + 低饱和墨绿；交互轻、动效短，像一个安静的纸本。

1.5 成功指标

≥ 3 天 / 周有内容的日记天数（核心）
≥ 60%草稿最终被提交锁定（说明「愿意封存」）
9 / 9首次使用一周内设置的问题数（说明提示被用上）

说明：以上为定性目标；本机应用无埋点，指标通过「导出 JSON 后自查」获得，不做任何自动上报。

03核心概念与数据

3.1 名词

名词定义
问题板全局唯一的 9 个写作提示，固定 3×3 网格，但只有 9 个格子（最多 9 条），不随日期变化。
日记条目以日期（YYYY-MM-DD）为键的一条记录，含正文与状态。
草稿状态为 draft 的条目，可反复修改，跨天未提交会被自动锁定。
锁定状态为 locked 的条目，永久只读；手动提交与跨天自动锁定两条路径。
字数去掉所有空白字符后的字符数；中英文、标点均按 1 计。

3.2 数据结构

// localStorage["writing-diary:v1"]
{
  "questions": ["…", "…", "", …],        // 固定长度 9，空串表示未设置
  "settings": { "skin": "paper", "fs": "m", "wallv": 42, "exportedAt": "2026-10-23T14:20:05.118Z" },
  "entries": {
    "2026-10-21": {
      "date": "2026-10-21",
      "content": "今天下午下了很久的雨……",
      "wordCount": 39,
      "status": "locked",                // draft | locked
      "createdAt": "2026-10-21T00:10:22.004Z",
      "updatedAt": "2026-10-21T00:20:11.512Z",
      "lockedAt":  "2026-10-21T00:20:11.512Z"
    }
  }
}
字段类型说明
questions[i]string第 i 格问题，最长 50 字；空串 = 未设置。
settings.skinstringpaper / cozy / focus / press / cute / tech，缺省 paper。非法值按 FR-11 的迁移规则回退。旧版 settings.theme（light / dark）只作迁移来源，读到时自动改写为 skin，字段保留不删。
settings.fsstring正文字号档位 s / m / l（FR-16），缺省 m；非法值回退 m。
settings.exportedAtISO string | null上一次成功导出备份的时刻（FR-10「上次备份」），缺省 null = 从未导出。只用于提示，不参与导出内容。
settings.wallvnumber壁纸浓度 0–100 连续值（0 = 最模糊最淡，100 = 最清晰），缺省 42。旧版 settings.wall 0/1/2 已废弃，仅作历史数据保留。
entries.{date}.contentstring原文，保留换行与空格（字数统计时才去空白）。
statusstringdraft 可编辑；locked 只读。
createdAt / updatedAtISO string首次落库时间 / 最后一次保存时间。
lockedAtISO string手动提交 = 提交时刻；跨天自动锁定 = 该日 23:59。

3.3 存储键

键内容说明
writing-diary:v1问题板 + 偏好 + 全部日记单条 JSON；导出备份即取此对象。
writing-diary:wallpaper压缩后的 JPEG data URL单存，避免与日记混在一起；不进入导出文件。

3.4 条目状态机

不存在— 首次输入非空 —▶ draft 草稿— 提交 / 跨天 —▶ locked 锁定
draft 草稿— 内容清空 —▶ 删除 　|　 draft 草稿— 跨天且内容为空 —▶ 删除

锁定是单向的：locked 不存在回到 draft 的路径，界面上也不提供任何撤销入口。

04功能需求

共 17 条。每条包含：目标、交互与规则、异常分支、验收标准。优先级均为 P0（当前版本已实现）。

FR-01九宫格问题板 已实现

目标：让用户预先写下 9 个「问自己的问题」，写作时不用面对空白页。

规则细节
数量固定 9 格，3 列 × 3 行；不支持增删格子。
编辑点格子 → 底部浮层「添加问题 / 编辑问题」，显示「第 N 格」；底部实时显示 n/50。
长度单条上限 50 字（maxlength=50，保存时再 slice(0,50)）；连续空白折叠为一个空格、首尾去空。
空值保存空内容 = 清除该格，不写入空串以外的东西；提示「空问题已清除」。
删除已有内容的格子，浮层内提供「删除」按钮，二次无需确认（可重新填写）。
示例9 格全空时，页面顶部出现说明块 +「填入一组示例问题」，一键写入 9 条默认问题（可逐格修改）。
作用域问题板全局唯一，不随日期变化；只存问题，不存答案；历史日记不会因为改问题而变化。

验收：① 9 格均可独立编辑；② 超过 50 字被截断且计数正确；③ 保存空内容后该格回到「＋添加问题」；④ 示例填充后 9 格全部有内容且可改；⑤ 修改问题后，已锁定日记正文不变。

FR-02写日记（每天一篇） 已实现

目标：打开就能写，写到一半也不会丢。

规则细节
对象只写「今天」，一天一篇；不能选日期、不能补写历史。
页头显示「2026年10月21日 周三」+ 副标题两种状态之一：提交前可随时修改 / 已锁定 + 提交于 hh:mm。
